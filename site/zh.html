轻量网关，职责清晰

你的评论就是起点。

01 / 连接

在工作发生的地方接入

接收来自 Forgejo、GitHub 或 GitLab 的签名 Webhook。无法创建 Webhook 时，也可以使用轮询接入。

02 / 路由

将提及转为请求

网关验证事件，检查用户和仓库权限，并将来源 URL 和消息传给智能体。

03 / 执行

智能体负责完成任务

智能体读取上下文、编辑检出的代码、验证改动，并在代码平台回复。网关不负责构建智能体的上下文。

选择你的工具链

不同的智能体，
同一个入口。

使用 Codex、Pi、Claude Code、Antigravity CLI、Kimi 或配置的自定义智能体。模型选择遵循适配器的默认设置，除非你明确配置或指定模型。

查看配置 ↗

让对话持续进行

每个讨论串的会话都会保留上下文。支持此功能的适配器可在运行中接收后续消息；其他适配器则将下一轮消息加入队列。

了解任务进展

通过网页状态、运行详情和实时输出查看正在运行及排队中的任务。对用户的提及可以触发浏览器通知。

控制谁能运行哪些任务

通过用户和仓库策略控制请求权限。配置的智能体用户通过 cgroup 执行器，以独立的 Linux 账户运行。

从检出代码开始

让下一个议题
拥有一个智能体。

构建二进制程序，配置代码平台和智能体用户，然后验证设置。你需要 Rust、支持 cgroup v2 的 Linux 主机、代码平台令牌，以及已完成身份验证的智能体 CLI。

部署指南 ↗
终端 / 快速开始
git clone https://github.com/AgentaaU/forge-bot.git
cd forge-bot
cargo build --release

cp config.example.toml forge-bot.toml
$EDITOR forge-bot.toml

# 启动服务前验证配置
cargo run -- check
cargo run -- serve

至少配置一个智能体用户，并指定且仅指定一个默认用户。服务安装、凭据和 Webhook 设置请参阅部署指南。
